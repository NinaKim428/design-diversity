# Design Diversity

> Claude가 만드는 PPT·웹 디자인이 늘 비슷해 보이는 문제를 푸는, 복붙 가능한 디자인 팩 카탈로그.

## 왜 — 천편일률 문제

생성형 AI에게 "PPT 만들어줘", "랜딩페이지 만들어줘"라고 하면 결과물이 서로 닮는다. 같은 그라디언트, 같은 둥근 카드, 같은 산세리프. 모델이 "안전한 평균"으로 수렴하기 때문이다.

**Design Diversity**는 그 평균에서 벗어나기 위한 카탈로그다. 스위스 그리드, 네오브루탈리즘, 에디토리얼 매거진, 다크 터미널, 클레이모피즘처럼 **서로 뚜렷하게 구별되는 디자인 스타일**을, AI가 그대로 재현할 수 있는 정밀한 지시문으로 명세화했다.

## 무엇 — 디자인 팩

각 팩은 하나의 디자인 스타일을 자기완결적으로 명세한 폴더다. `design-packs/{slug}/` 안에 네 파일이 있다.

| 파일 | 역할 |
| --- | --- |
| `prompt.md` | Claude Code에 **한 블록으로 복붙**하면 그 스타일을 재현하는 디자인 지시문. 가장 중요한 산출물. |
| `tokens.json` | 색·타이포·간격·셰이프를 담은 머신리더블 디자인 토큰. |
| `preview.png` | 그 스타일로 렌더한 샘플 미리보기. |
| `meta.yaml` | 메타데이터, 디자인 원리를 학습한 출처, 라이선스 고지. |

**현재 카탈로그: 40팩**
- PPT 트랙 20팩 — 컨설팅 정밀그리드, Keynote 미니멀, 스위스 에디토리얼, 네오브루탈리즘, 바우하우스, 럭셔리 세리프 등
- 웹 트랙 20팩 — 스위스 그리드, 다크 터미널, 클레이모피즘, 글래스모피즘, Y2K 크롬, 리소그래프 프린트 등

각 팩은 5개 스타일 축으로 분류된다: **color · type · layout · space · motion**.

## 어떻게 쓰나

1. [카탈로그 사이트](#카탈로그-사이트)에서 또는 `design-packs/` 폴더를 직접 훑어 원하는 스타일을 찾는다.
2. 그 팩의 `prompt.md` 전문을 복사한다. (사이트에는 원클릭 복사 버튼이 있다.)
3. Claude Code 또는 다른 AI 도구에 붙여넣고 이렇게 요청한다:

   > 위 디자인 팩 지시를 그대로 따라서, [내 주제]로 슬라이드 덱(또는 웹페이지)을 만들어줘.

4. `tokens.json`은 코드에서 디자인 토큰을 직접 소비하고 싶을 때 쓴다.

`prompt.md`는 모호어("모던하게", "깔끔하게") 없이 검증 가능한 구체 지시만 담도록 작성됐다. 그래서 AI가 스타일을 추측하지 않고 그대로 재현한다.

## 카탈로그 사이트

`site/`에 Next.js 15 (App Router + TypeScript) 정적 카탈로그 웹사이트가 있다. 빌드 타임에 `catalog.json` + `design-packs/`에서 정적 생성(SSG)되며 런타임 DB가 없다.

```bash
cd site
npm install
npm run dev      # 로컬 개발 서버
npm run build    # 정적 빌드
```

- **홈** — 팩 그리드 갤러리, 트랙·스타일 축 필터.
- **팩 상세** — 큰 미리보기, `prompt.md` 전문 + 원클릭 복사 버튼, `tokens.json` 색 스와치 시각화, 출처.

## 기여

새 디자인 팩을 추가하고 싶다면 [CONTRIBUTING.md](./CONTRIBUTING.md)를 참고하라. 팩 파일 규격, 슬러그 규칙, `catalog.json` 갱신 절차가 정리돼 있다.

## 라이선스 / 저작권

이 레포가 배포하는 것 — **디자인 명세(`prompt.md`)·토큰(`tokens.json`)·문서** — 은 [MIT 라이선스](./LICENSE)로 제공된다.

각 팩은 공개 디자인 시스템·스타일에서 학습한 **시각 원리의 명세**이며, 특정 제품의 상표·로고·독점 자산을 재배포하지 않는다. 각 팩이 디자인 원리를 학습한 출처는 해당 팩의 `meta.yaml`에 기재돼 있고, 원자산은 각 출처의 라이선스를 따른다.
